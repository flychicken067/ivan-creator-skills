# Ivan Skill Value Cover

把抽象的 Skill 说明变成一张不需要阅读方法论也能看懂的横版封面。

## 开始前

从用户输入或附件中提取：

- Skill 名称与一句话能力
- 真实使用者及工作场景
- 使用前收到的原始问题、附件或混乱材料
- 使用后可以直接拿走的结果
- 必须保留的品牌、产品或事实约束

缺少信息时只追问最影响画面的 1–2 项；可以从已有附件可靠判断时不要重复询问。不得虚构产品功效、数据、批准信息或客户评价。

## 封面叙事

优先用一个真实人物贯穿左右两侧：

- 左侧是“输入”：人物面对真实工作麻烦，例如直播弹幕、客服私聊、散乱产品文档、竞品网页或产品需求。
- 右侧是“输出”：同一个人已经拿到能继续工作的具体成果，例如带来源的答案卡、证据对比表、可确认页面或研发任务包。
- 中间只用一个轻量的 Skill 转换符号连接，不画复杂流程图。

价值差异必须通过人物状态、信息秩序和真实交付物体现，而不是只写“Before / After”。

## 视觉要求

- 横版 16:9，主体在缩略图尺寸下仍清楚。
- 现代产品摄影与编辑设计结合，克制、高级、可信；避免文字 PPT、赛博大屏、廉价渐变和堆叠卡片。
- 画面最多保留：Skill 名称、一句价值主张，以及输入/输出各一个极短标签。
- 中文必须短、准确、可读；如果图像模型无法稳定生成中文，先生成无字视觉底图，再使用编辑/排版能力叠加文字，不接受乱码。
- 默认暖白与中性色背景；品牌强调色只用于一个动作或关键结果。
- 健康、金融、法律或其他受监管内容只显示用户提供且已经确认的事实；无法确认时使用中性占位物，不生成未经证实的结论。

## 输出

先用一句话复述封面的叙事，再生成封面。交付时同时给出：

1. 最终横版封面
2. 封面标题和一句价值主张
3. 画面中的“输入”和“输出”分别代表什么
4. 若信息不足，明确标出仍是占位的内容

用户要求多方案时，改变叙事角度，不要只换颜色。
